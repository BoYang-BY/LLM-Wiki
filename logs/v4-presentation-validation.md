# V4 簡報生成與驗證

執行日期為 2026-11-22（台北）。以已核准的 [V3 教學稿](../presentation/teaching-outline.md) 及其 Wiki 段落為規格，在使用者確認關卡後生成 [12 頁簡報](../presentation/index.html)。教材保留每頁學習目標及可展開的 Wiki 證據。案例中的電影、評分與熱門度均為教學設定。沿用 Wiki 已驗證的內容與來源範圍。

## 問題、修正與重跑

| 節點 | 實際發現 | 原因與回跑 |
|---|---|---|
| 簡報測試 | 首次無頭 Edge 啟動時 GPU 程序反覆崩潰。另一次 CDP 連線等候頁面回應時逾時。 | 測試環境中的 Edge 子程序無法正常完成啟動。使用工具核准的本機無頭 Edge 與暫存設定檔後取得可用的瀏覽器。此步重跑瀏覽器測試。 |
| 簡報測試 | 測試回報無法找到簡報素材，診斷時發現實際連到 Edge 擴充功能的背景分頁。 | 初版測試選取第一個 CDP target。改選 type 為 page 的目標，並停用臨時瀏覽器設定檔中的擴充功能，確認載入正確的本機檔案後重跑。 |
| 簡報測試 → HTML/CSS | 功能測試通過後，尺寸檢查在 320px 發現橫向溢出。 | 章節下拉選單的寬度在窄視窗下超過頁首可用空間。修正選單縮放與上限，重跑四種尺寸的全部頁面，包含展開 Wiki 證據後的寬度。 |
| 簡報測試 → JavaScript | 回首頁的截圖顯示頁首頂部被捲出畫面。 | 程式設定 location.hash 後，瀏覽器錨點捲動覆蓋了頁首定位。改用 History API 更新網址，並處理返回與重新整理時的捲動。複驗回首頁的 scrollY、鍵盤切頁、瀏覽器返回及重新整理。 |

## 最終測試

- 靜態檢查通過。HTML 有 12 頁、12 個學習目標、12 區 Wiki 來源、46 個唯一 ID 與 75 個有效相對引用。SVG 通過 XML 解析，Wiki Lint 檢查 85 個本機連結。
- 本機 Edge 以 file:// 開啟。CSS、SVG 與簡報互動正常。38 項功能檢查通過，涵蓋上／下一頁、章節直達、鍵盤切頁、控制項焦點保護、偏好訊號、矩陣、三階段、內容比對、評估、冷啟動、模擬器及測驗。
- 模擬器對照 V3 驗證 A 預設、A 選科幻、切換 B、B 選喜劇、B 重設、回 A。核對每一步的完整清單與逐筆理由，並確認切換偏好後保留控制項焦點。
- 驗證三道測驗的六個選項及對應解析。另用瀏覽器鍵盤輸入測試方向鍵，驗證瀏覽器返回與重新整理後的頁碼及捲動位置。測試期間沒有未捕捉的 JavaScript 例外。
- 1440×900、1024×768、390×844、320×568 四種 Edge 視窗均遍歷 12 頁，未發現橫向溢出。另於桌面尺寸檢視首頁與模擬器截圖。測試使用 Edge 的本機檔案模式，未另外啟動 VS Code Live Server 或其他瀏覽器。

## Workflow 反思

本輪可重現的簡報回修集中在測試節點。窄版溢出與錨點捲動均有瀏覽器證據，需回到 HTML 生成節點修 CSS 或 JavaScript 後重跑。技術主張核對沿用 V3，無須回到 Query、Ingest 或 Wiki 維護。

主 Graph 保持「教材驗證 → 使用者確認 → HTML 生成 → 簡報測試」。V4 的測試子流程由先跑完整互動再檢查版面，改為未來在首版可預覽時先做最窄視窗與首頁返回的快速檢查，再跑全頁、互動和來源複驗。原因是溢出與錨點捲動不必等待其餘功能完成即可測出。提前檢查的成效待下一次執行比較。
